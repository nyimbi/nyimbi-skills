# Storage and Caches

## Thresholds

| Condition | State | Action |
|---|---|---|
| Free < 10 GB or < 2% | Critical | Clear a safe category before any install, model pull, or Xcode update |
| Free < 20 GB or < 5% | Warning | Plan a cleanup before the next large download |
| Free ≥ 20 GB | Adequate | Keep 20 GB reserve; monitor monthly |

A 4 TB disk with 132 GB free is 3.6% but has ample absolute headroom. Use the absolute
number for the decision and the percentage as context.

## What is safe

| Category | Why | Method |
|---|---|---|
| Homebrew downloads | Re-downloadable | `brew cleanup -s` |
| npm / Yarn / pnpm / Bun caches | Re-downloadable | native cache clean |
| pip / uv / Go build caches | Re-downloadable | native cache clean |
| RubyGems cache | Re-installable | `gem cleanup` |
| Xcode DerivedData | Rebuilt on next build | delete contents; skip if Xcode runs |
| Unavailable simulators | Recreatable | `xcrun simctl delete unavailable` |
| Docker dangling images and build cache | Rebuildable | `docker system prune -f` only |
| Project build artifacts | Regenerated by the project | delete named dirs under registered roots |
| Old user logs | Diagnostic history | quarantine files older than 30 days |
| Old Downloads | User files | quarantine files older than 90 days |
| Old installers | Re-downloadable | quarantine DMG/PKG/ZIP older than 30 days |

## What is caution

- **User caches** (`~/Library/Caches`): some apps rebuild, some log you out, some lose
  local state. Clean per app or leave it; never `rm -rf` the whole folder.
- **Playwright browsers**: large but re-downloadable. Remove old revisions, not the
  current one.
- **Conda packages**: `conda clean --all` can force re-solves. Use only when space is
  tight.
- **iOS backups**: user data. Quarantine only, with explicit consent.
- **Xcode archives**: build history and dSYMs. Quarantine only.
- **Trash**: irreversible. Only `trash-empty` with `--yes`.

## What is never

- Hugging Face cache and model weights.
- `~/src`, documents, photos, mail, messages, calendars, contacts.
- `~/Library/Application Support` and `~/Library/Preferences`.
- `/private/var/vm`, swap, sleep image.
- System caches and logs.
- Time Machine snapshots without a recent backup.

## Project build artifacts

Registered roots: `~/src`, `~/Developer`, `~/Projects`, `~/code`, `~/repos`, `~/work`.
Eligible names:

```text
node_modules  target  build  dist  .next  .nuxt  .gradle  DerivedData
Pods  .venv  venv  __pycache__  .pytest_cache  .mypy_cache  .ruff_cache  coverage
```

Rules:

- Only under a registered root, at depth ≤ 5.
- Never follow symlinks.
- Never remove a directory containing `.git` at its root.
- `node_modules` is regenerable but expensive; list it and let the user choose the
  project. `mac_apply.py --category project-artifacts --root <path>` scopes the run.
- After deleting, re-run the project's install command and its tests.

## APFS and snapshots

`tmutil listlocalsnapshots /` lists local Time Machine snapshots. macOS uses them for
local recovery and may report them as purgeable. Do not delete them to make a number
look better. If space is critical and the last backup is recent, deleting a specific
snapshot is a manual decision with `tmutil deletelocalsnapshots <date>`.

`df` reports volume free space; APFS may show purgeable space separately. The audit
records root and Data volume values plus snapshots.

## External drives

The skill audits only the boot volume and the home directory. External volumes,
`/Volumes/*/.Trashes`, and network shares are out of scope; use Finder or Disk Utility
and verify the volume before deleting anything.

## Verification

```bash
python3 scripts/mac_audit.py
python3 scripts/mac_plan.py
```

Compare:

- free bytes before and after;
- the affected category size;
- the number of files in quarantine;
- whether the app or project still works.
