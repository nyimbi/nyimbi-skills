# Personal Context

Editable defaults for strategy work on this machine. Change these when the situation changes;
do not put passwords, customer lists or unpublished financials here.

## Principal

- Nyimbi Odero, software engineer, Nairobi.
- Works on payment rails, identity systems and local-first AI.
- Builds and operates systems directly; not a slide-only strategist.

## Defaults

| Dimension | Default | Consequence for the work |
|---|---|---|
| Team | 1–5 people | No staff functions; every initiative has an opportunity cost |
| Capital | constrained | Prefer reversible pilots, capital-light entry and build-versus-buy |
| Time | 100-day execution horizon | Plan in days and weeks, not quarters of headcount |
| Strategy horizon | 18 months | Long enough for a moat argument, short enough to test |
| Geography | Kenya / East Africa first, then remote | Regulatory and payment-rail realities are first-class constraints |
| Compute | local-first, Apple Silicon | Avoid advice that assumes a cloud data team or GPU fleet |
| Evidence | primary sources, dated | No unsourced market numbers; no invented benchmarks |
| Output | memo first | Decks only for external capital or a board |

## Standing constraints

- Payment and identity work carries regulatory exposure; name the regime before recommending
  a move.
- A solo or small team cannot run two big bets at once. The kill list matters as much as the
  priority list.
- Local-first AI means model and data choices are part of the strategy, not an implementation
  detail.
- Cash runway is a hard constraint, not a slide.

## What "personalized" means here

1. Recommendations must fit a small team: fewer workstreams, clear owners, reversible steps.
2. The financial model uses the user's actual unit economics, not a sector benchmark.
3. The memo is written for a decision-maker who will implement it, not for a committee.
4. The 100-day plan is the default execution artifact.
5. A recommendation that requires a function the user does not have is a non-answer.
